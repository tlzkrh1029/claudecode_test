# NVT Signal 역추적 결과

## 확인된 사실 (차트 레이아웃에서 직접 확인)

- 두 번째 열 지표는 gliderfund가 게시한 보호 스크립트 **"NVT (original) - Network Value to Transactions"**(tradingview.com/script/50VFVta2)의 **버전 1**입니다. 스크립트 ID는 `PUB;mGO6NQAZK4oHjEzHPwWWWTIYWDGJkBQF`이며, 네 번째 열은 같은 스크립트의 버전 2(2024-11-05)입니다.
- 차트에 저장된 입력값은 `Transaction Period = 90`, `Force Daily View across all Time Frames = false`(기본값은 true), `Length Signal = 13`, `Manual Above/Below Value Levels = false`입니다.
- `Force Daily View`를 끈 상태이므로 이동평균이 차트 봉 기준으로 계산되고, 그래서 시간 단위마다 기준선이 달라집니다.
- 입력값 이름, 플롯 구성, 색상 팔레트는 공개 메타데이터와 일치하게 재구성했습니다. 소스 코드 자체는 암호화되어 있어서, 계산식과 자동 기준선 규칙은 여전히 추론입니다.

## 표시 규칙 확정 (Cowork 2차 검증)

Cowork가 4H, 1D, 2D, 5D, 1W, 2W, 1M에서 원본의 plot 값을 봉 단위로 추출했고, 아래 규칙은 모든 봉에서 일치했습니다.

| 항목 | 규칙 |
|---|---|
| 자동 기준선 (상단/하단) | 분봉 200/60, 일봉 계열 150/45, 주봉 계열 450/100, 월봉 1000/333 |
| 기준선 표시 | NVT가 기준선을 넘은 봉에서만 값이 있고, 그 외에는 na입니다. |
| 캡 라인 | `ta.highest(nvt, 365)`, `ta.lowest(nvt, 365)`를 씁니다. `bar_index < 364`이면 `상단 × 1.1`, `하단 / 1.1`을 씁니다. |
| NVT 선 색상 | 하단 미만 #00FF00, 상단 초과 #FF0000, 그 사이 #474747 |
| 신호선 | `ta.ema(nvt, 13)` |
| 교차 표시 | crossover는 Bullish, crossunder는 Bearish이며, 점은 신호선 값 위치에 찍힙니다. |
| 라벨 | 마지막 봉의 NVT 위치에 "NVT"(labelup, tiny)를 표시합니다. |
| 시작 시점 | 2011-08-18 이전에 끝나는 봉에는 값이 없습니다. 원인은 모르므로 날짜 조건으로 재현했습니다. |

재구성 NVT와 원본의 비율은 2014년 이후 중앙 오차 0.02~0.3%입니다. 2011~2013년에는 수 퍼센트의 오차가 남아 있습니다.

아직 확인하지 못한 것은 `Force Daily View = true`일 때의 기준선, Night Mode, Highlight 옵션을 끈 경우입니다.

## 계산식 확정 (차트에서 추출한 값으로 검증)

Cowork로 차트에서 추출한 1D/1W/1M 값(`tv_nvt_*.csv`)과 Quandl BCHAIN 원본 데이터(2009-01 ~ 2021-11)를 대조한 결과입니다.

- **3열 aamonkey**: `MKTCP / sma(ETRVU, 90) / 4`와 오차 1e-8 수준으로 완전히 일치합니다. 차트와 분석에 쓴 데이터가 같다는 뜻입니다.
- **2열 gliderfund v1**: `close × TOTBC / request.security(ETRVU, timeframe.period, ta.sma(close, 90))`와 일치합니다.
  - 1D, 2014년 이후: 중앙 오차 0.07%, 상위 5% 오차 0.8%
  - 1M: 첫 값 시점(2016-06)까지 재현되며, 중앙 오차 0.05%
- 2열과 3열의 비율이 정확히 4가 아닌 이유는 분자가 다르기 때문입니다. 2열은 차트 종가 × 공급량을 쓰고, 3열은 blockchain.com의 시가총액(MKTCP)을 씁니다.
- 1M에서 2열이 3열보다 9개월 먼저 시작하는 이유는 이동평균을 계산하는 봉이 다르기 때문입니다. 2열은 데이터 심볼 자체의 봉(2009-01부터)으로 계산하고, 3열은 차트의 봉(2009-10부터)으로 계산합니다.

## 결론

두 번째 열 지표는 aamonkey 코드에서 `/ 4`를 제거한 고전적인 NVT Signal일 가능성이 가장 높습니다.

```
NVTS = MKTCP / sma(ETRVU, N)   // N = 차트 봉 기준 길이, 기본값 90으로 추정
```

- 데이터 피드는 `QUANDL:BCHAIN/MKTCP`(시가총액)와 `QUANDL:BCHAIN/ETRVU`(추정 온체인 거래량, USD)이며, `security(sym, 'D', close[0])`로 불러옵니다.
- 이동평균은 일별 90일이 아니라 **차트 봉 90개**를 기준으로 계산합니다. 따라서 주봉에서는 90주, 월봉에서는 90개월을 평균합니다.
- 과매도/과매수 기준선은 `timeframe.isdaily / isweekly / ismonthly`로 구분하여 45/150, 100/450, 333/1000을 적용합니다.
- 선 색상은 과매도 구간에서 녹색, 과매수 구간에서 빨간색, 그 사이에서 검정색입니다.

## 근거

1. **개형이 똑같고 값만 다르다는 관찰**은 상수배 관계로 가장 잘 설명됩니다. aamonkey 코드는 `nvt = (marketCap/out1) / 4`이므로, 길이가 같다면 두 번째 열의 값은 모든 봉에서 세 번째 열 값의 정확히 4배가 됩니다. 다만 이 관계는 대수적으로 도출한 것이며, 원본 지표의 값을 직접 측정해서 확인한 것은 아닙니다.
2. **일봉 45/150**은 Willy Woo(2018)와 Obvious Capital이 제시한 고전적 NVT Signal(나누기 4를 적용하지 않은 값)의 기준선입니다. `/4`를 적용한 값은 2011~2021년 동안 어떤 시간 단위에서도 과매수 기준선에 한 번도 도달하지 못합니다(11개 고점 중 0개).
3. **주봉과 월봉 기준선이 더 크다는 점**은 이동평균이 차트 봉 개수로 계산된다는 사실과 부합합니다. 거래량이 장기적으로 증가해 왔기 때문에, 90주나 90개월 평균은 현재 거래량보다 작고, 그 결과 NVT 값이 커집니다. 실제 Quandl BCHAIN 데이터(2010-08 ~ 2021-11)로 계산한 결과는 다음과 같습니다.

| 시간 단위 | 기준선 (OS/OB) | 주요 저점 | 주요 고점 |
|---|---|---|---|
| 1D | 45 / 150 | 2015-01: 43, 2011-11: 12 | 2017-12: 172, 2021: 196~276 |
| 1W | 100 / 450 | 2015: 55, 2018-12: 64 | 2017-12: 676, 2021: 584~852 |
| 1M | 333 / 1000 | 2018-12: 194, 2020-03: 223 | 2021-03: 1220 |

   반대로 일별 90일 이동평균을 모든 시간 단위에 고정해서 사용하면, 주봉 최댓값은 353, 월봉 최댓값은 262에 그칩니다. 이 경우에는 450과 1000 기준선에 절대 도달할 수 없으므로, 이 가설은 기각됩니다.

## 확정되지 않은 부분

- **길이 N**: 2010~2021년 데이터로 보면 N이 대략 75~120 범위에 있을 때 세 가지 기준선이 모두 비슷하게 잘 맞습니다. N이 85~95 범위라면 aamonkey 선과의 차이를 눈으로 구별하기 어렵습니다. 세 번째 열이 "더 긴 길이처럼 보인다"는 관찰이 실제 차이라면, 원본 지표는 80~89 정도의 약간 짧은 N을 사용하고 있을 수 있습니다.
- **데이터 피드**: TradingView의 최신 Pine 레퍼런스에는 QUANDL 심볼 요청이 더 이상 유효하지 않다고 적혀 있습니다. 그런데 차트에서는 세 번째 열이 여전히 그려진다고 하셨으므로, 해당 계정에서 QUANDL 티커가 아직 동작하는지 확인해야 합니다. 동작하지 않는다면 코드의 심볼 입력값을 대체 피드로 바꿔야 합니다.
- **분봉 동작**: 원본 지표가 분봉에서 어떤 기준선을 사용하는지는 확인하지 못했습니다. 재구성 코드는 분봉에서 일봉 기준선을 사용합니다.

## 차트에서 검증하는 방법

1. 두 번째 열 지표의 **설정 > 입력값** 탭을 엽니다. 보호된 스크립트여도 입력값 목록은 볼 수 있습니다. 길이 입력값이 있다면 그 값을 `nvt_signal_reconstructed.pine`의 `Transaction MA length`에 똑같이 입력합니다.
2. `nvt_candidates_diagnostic.pine`을 차트에 추가하고 `Show`를 `Ratios`로 바꿉니다. 그다음 `Original NVT line`에서 두 번째 열 지표의 NVT 선(기준선이 아닌 선)을 선택합니다.
3. 데이터 창에서 `R1`이 모든 봉에서 1.000, `R2`가 4.000이면 결론이 확정됩니다. `R1`이 1 근처에서 흔들린다면 `Alternative length`를 조정하여 `R7`이 1.000으로 평탄해지는 값을 찾습니다.
4. 차트를 1D에서 1W와 1M으로 바꿔 봅니다. 원본 지표의 값이 `C1`과 함께 변하면 차트 봉 기준 이동평균이 맞습니다. 반대로 `C3`처럼 값이 변하지 않는다면, 원본은 일별 이동평균을 고정해서 사용하고 있는 것입니다.
5. 추가로 확인할 수 있는 예측은 다음과 같습니다. 2010년부터 데이터가 있는 심볼이라면 월봉 선은 2017-12 또는 2018-01부터 시작되고, 주봉 선은 2012-04 또는 2012-05부터 시작됩니다. 2W 차트에서는 선이 녹색으로 표시되는 구간이 거의 없어야 합니다.

## 파일

- `nvt_signal_reconstructed.pine`: 두 번째 열 지표를 재구성한 Pine v6 코드입니다.
- `nvt_candidates_diagnostic.pine`: 후보 공식 9개와 원본 대비 비율을 함께 표시하는 진단용 Pine v6 코드입니다.
